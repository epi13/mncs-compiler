## Workload

The compiler's `flow.mncs` module imports the existing declaration compiler
and calls its `prove_unit`/`parse_unit` pipeline. A Profile 0.18 caller with a
small function body compiles successfully against the Profile 0.13 declaration
module. The native body interpreter and the production `mncs call` path both
stop while entering `mncs.compiler.decl.v1::block_step`.

Both failures report argument 5 as a `BlockState` record whose canonical type
identity is textually identical to the expected `BlockState` identity. The
interpreter and research-bytecode paths therefore agree on the rejection, but
the exact mismatch inside the record/SSA validation is still to be isolated.

## Smallest current reproducer

From the compiler repository root, after bootstrapping the locked current
Stage-0:

```sh
MNCS_LIBRARY_PATH=src .bootstrap/target/debug/mncs call \
  src/compiler/flow.mncs \
  --module mncs.compiler.flow.v1 \
  --function lower_unit \
  --args .build/flow-args.json \
  --library src \
  --step-budget 8000000 \
  --no-cache
```

`.build/flow-args.json` is generated by `tools/test_flow.py`; it supplies four
bounded byte chunks and the 91-byte Profile 0.18 source
`mncs 0.18; module pressure.flow; fn f(x: bool) -> (r: u64) { if x { return 1; } return 2; }`.

Observed result: `invalid_request`, backend `mncs-research-bytecode`, 956,379
steps, at imported `decl::block_step`, argument index 5. The compiler emitted
and reused artifact `mncs:compiler:backend-artifact:94b2312668b982083008f22bc054f237332897eacc00f903213dd60b6f0e8cad`.
The Stage-0 `BodyExecutionSession` probe fails at the same function, same
argument, same step count. The exact pre-fix reports are preserved in
`evidence/flow-failure.json`.

## Classification and Commons reconciliation

The source compiles, imports resolve, the artifact is produced, and execution
reaches the linked dependency. This is not evidence of missing syntax or a
new language feature. It is a typed-value validation failure in the linked
runtime/SSA path; the correct owner may be `mncs-language` runtime or backend
implementation after the nested value shape is reduced further.

Commons `EVT-5B0D821A94F41F1B` associates old CP-0001 with the Store's bounded
sequence pressure. That is a separate source-representation observation. The
resolved CP-0008 record concerns compile-time finite-payload visibility, not
this post-compilation execution failure. Commons main has no matching
linked-record runtime finding, so this compiler-originating reproducer is kept
here first and no duplicate family pressure was filed.

## Resolution criterion
